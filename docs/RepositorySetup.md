# 仓库上线配置

以下设置需要仓库管理员在 GitHub 网页端完成，仓库文件不能代替这些权限配置。

## 必须确认

- [ ] 确认 GitHub 组织、仓库长期持有人和至少两名管理员。
- [ ] 在 `.github/CODEOWNERS` 填入真实 GitHub 团队或账号。
- [ ] 在 Settings → Pages 中选择 GitHub Actions 作为发布源。
- [ ] 确认正式使用 Pages 默认域名、独立域名还是学校域名。
- [ ] 为 `main` 创建分支保护规则。

## `main` 分支保护建议

- 要求所有修改通过 Pull Request。
- 要求至少一名审核者批准。
- 新提交后撤销过期批准。
- 要求 `check / validate` 状态检查通过。
- 要求对话全部解决后才能合并。
- 禁止强制推送和删除分支。
- 限制直接推送权限。

## 发布权限

`deploy.yml` 仅在 `main` 更新或手动触发时发布。工作流使用最小权限，构建失败不会执行部署步骤，也不会覆盖现有站点。

## 演示 Pull Request

正式开放贡献前建议准备两个临时分支：

1. 正确示例：修改普通文案并通过全部检查。
2. 错误示例：添加失效内部链接或非英文文件名，确认 CI 会阻止合并。

演示完成后删除临时分支，不把故意错误合入 `main`。
